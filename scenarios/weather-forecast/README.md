# 天气预报

每天发一个城市的天气，一条短视频讲完三件事：今天什么样、未来七天怎么变、出门要带什么。

## 给谁看

住在这个城市、早上出门前想花一分钟知道今天冷不冷、下不下雨的人。所以发布时间要赶在大家出门前，内容也别贪多：今天概览说细，七天说个大概，最后给一句能直接照着做的建议，比如带伞、加衣服、适合洗车。

## 每天几点发

推荐早上 7 点前发出去。几点开工倒着推：取数、写稿、做片、验收一共留一个多小时，6 点开工差不多。改时间改根目录 `config.yaml` 的时间那一组，这个玩法自己的配置里也有一个发帖时间，写着提醒你对齐。

## 数据从哪来

只用一个源：Open-Meteo（网址 `https://open-meteo.com`）。

- 免费，不用注册，不用密钥。打开就能取。
- 取法手把手写在同目录的 `sources.md` 里，一条命令拿七天预报，字段意思一句一个。
- 数据是预报，不是实况。稿子里要带一句「出门前再看一眼实时天气」，别把预报说成定数。

## 城市怎么改

改本目录 `config.example.yaml` 里的城市和经纬度就行。经纬度不用自己量：用 `sources.md` 里写的查法，输城市名就能查到。换完城市，先手动取一次数，确认返回的是新城市，再让它自动跑。

## 有什么风险

这个玩法风险低，但有三条要守住：

1. **数据必须是当天的。** 每天开工重新取一次。取不到就停这一天，宁可不发，不许拿昨天的预报改个日期冒充今天的。
2. **极端天气别乱说话。** 台风、暴雨、高温这类，只报数据源给的数和官方提醒，不自己加判断，更不许吓唬人涨粉。
3. **数字要对得上。** 画面上、口播里、标题里的温度和降雨概率，必须跟取回来的数据一个一个对过。对不上就改稿，别改数据。

## 建议哪一档

半自动。数据是机器取的，偶尔会有怪值（比如降雨概率超过 100、温度明显不对），发布前人扫一眼就能拦住。跑稳了再想全自动的事。

## 示例说明

这个玩法的示例成品在程序里单独做，只用来给人看格式和效果，不会真的发到小红书上。你自己的号跑起来之后，才是你自己发。
