# 三家能力对照（详表）

小红书全自动化运营发布（适配muse、Chatgpt dots、Grok bots）

先声明：Grok 那一列写的时候没逐项实测，是按「应该能接、接法如此」写的。用之前自己验，不要当承诺。Muse 那一列是已经有账号在日更用的，ChatGPT 那一列按半自动设计。

| 能力 | Muse | ChatGPT | Grok |
|---|---|---|---|
| 读规矩、选题、写稿 | 能。skill 入口读 `core/`，按阶段读手册 | 能。项目文件放 `core/`，指令粘贴稿兜底 | 能。AGENTS.md 写了读取顺序 |
| 做片（网页做片流水线） | 能。脚本在本机跑，捕获加合成一条龙 | 能配合。脚本要在用户本机跑，输出贴回来验 | 有本地执行环境就能。没有就人工跑脚本回填 |
| 子 agent 编排 | 能。总管派单、串行、逐单验收，是原生路子 | 没有稳定的编排。一个 agent 按顺序自己做 | 未验证。以产品当时能力为准；弱了降级成单 agent 顺序执行 |
| 定时 | 能。日更、双看门狗、跟进、复盘，五件都能建 | 没有常驻定时。每天手动喊开工 | 未验证。没有就用系统 cron 到点拉起，或者手动 |
| 浏览器自动发布 | 有浏览器能力时能。先主站确认登录，再走站内入口 | 不能。主路是半自动：它备待发包，用户人工发 | 看产品浏览器能力。没有就半自动 |
| 发后跟进 | 能。发布后 2 小时内定时查、自动回 | 手动。用户在 App 看，或者把评论贴回来拟回复 | 手动，或者用 cron 拉起一轮跟进 |
| 周复盘 | 能。每周定时跑，还能顺手改 `core/` | 手动发起。台账贴给它，它给修改稿，人确认再落 | 手动或 cron 拉起 |

## 表外的话

三家差的只是「谁来按按钮」：谁到点开工、谁点发布、谁盯评论。

剩下的全一样：同一份 `core/` 规矩，同一个 `core/validate.py` 验收，同一个待发包格式（`video.mp4`、`cover.jpg`、`post.md`、`publish-checklist.md`）。

所以别拿「哪家更聪明」选平台。拿这三件事选：你能不能接受手动开工、手动发布、手动盯跟进。三件都能接受，哪家都行；一件都不能接受，就选 Muse 那条。
