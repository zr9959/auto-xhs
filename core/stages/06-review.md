# Stage guide 06 · Weekly review

> When to read: at weekly review time (time per the table). Read the constitution page first, then this guide, then the full lessons log (the copied `lessons.md`; if there isn't one yet, copy it from the template first) — review conclusions get appended to the lessons log.
> All numbers come from the constitution page's numbers table. This guide only cites them, never writes its own.

## Input

- This week's ledger (`paths.ledger_file`) entries and each entry's acceptance checklist.
- This week's owner feedback, run logs, and interaction state.

## Output

- Review conclusions written into the lessons log, dated. Entries that became fixed rules get promoted into the constitution page or the matching stage guide; outdated entries get deleted.
- Data backfill results, draft cleanup results, consistency patrol results.
- One summary sentence, sent to the reporting place.

## Evidence list to hand back to the manager

- How many posts this week, the category spread, the best and worst post each with the data behind it (when data hasn't come out yet, write "数据未出", data not out).
- Data backfill results item by item (numbers, or "仍未出 / 待回填", still not out / waiting for backfill).
- Draft cleanup: how many deleted, what each was; undeleted ones listed as a to-confirm list.
- Consistency patrol: each check's result and the mismatches found.
- Which rules this round changed, and why.
- The four elements for problems (write "none" when there are none).

## What a review does

Read this week's ledger and owner feedback, and look at: which categories did well by data or feedback, which post got called out, whether the platform has new rules, what new pitfalls got hit. Conclusions go into the lessons log (dated); ones that became fixed rules get promoted into the constitution page or the matching guide, outdated ones get deleted. Finally send one summary sentence: how many posts this week, which was the best, what rules changed.

## Data backfill (the reviewer's job)

Some data only comes out the day after publishing: impressions, cover click-through rate, follower growth, average watch time, and the like. At review time, check each of this week's posts for these numbers one by one, writing the numbers or "仍未出" (still not out) into that week's review entry.

- Published less than a day ago, with a field showing "-": mark it "待回填" (waiting for backfill). Next week's review fills in last week's waiting items first, then draws this week's conclusions.
- A field showing "-" is normal, not a problem, and not throttling. Same-day visible data (views, likes, saves, and the like) shows the same day; missing pieces get checked the next day — never invent numbers.
- When two data pages disagree on counting, note which page's numbers you adopted. Never average them yourself, never invent.

## Draft cleanup (done in passing at each review)

- Patrol the creator platform's draft box once. Confirmed useless old drafts — old versions already replaced by a formally published post, abandoned half-finished pieces — delete directly, and report in the review how many were deleted and what each was. When unsure whether one is still useful, don't delete — list it for the owner.
- Note: the web version's drafts live only in the browser that created them, on that machine — they don't sync with the account. So you can only clear drafts in the browser you use. Drafts the owner built on their own devices are invisible to you and undeletable by you — remind them to handle those themselves.
- Entering the platform follows the entry rule: main site, wide window, confirm login first, then the in-site entry — never open the creator platform's domain directly and draw conclusions.

## Monthly sensitive library maintenance

At the first weekly review of each month, do this: re-read the platform's rule announcements (community conventions, special governance announcements, and the like), and check whether the sensitive appendix has gone stale. A static word list goes stale in a few months — the platform's governance focus keeps moving. A new special campaign means updating the appendix, with one line in the review record stating what changed.

## Consistency patrol (done in passing at each review)

Search the constitution page, the guides, and the task briefs in full for key numbers and paths, checking item by item that each has only one version: start and publish times, the two watchdog times, sourcing time limits, voiceover word count, finished length, speed, subtitle band position, review time — each of these may have only one statement.

When another file cites an old number or old path, only report the difference and the evidence — never silently mix them. Once the constitution page is confirmed as the authority, fix them all up in one pass.
